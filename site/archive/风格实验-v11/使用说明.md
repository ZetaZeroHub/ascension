首帧由内置 imagegen 参考重绘，视频由本机 ComfyUI + MiniMax H3 + 风格 LoRA 生成。四种具体材料设计主要依赖参考图与首帧重绘，不应把它们全部归因于某一个适配器。

## 规格与耗时

本轮是选风格的无声试片：每段 73 帧、24fps、3.0417 秒，Turbo 8 步。H3 原生生成 640×384，中心裁切到 640×360，再用 Lanczos 精细缩放至 1280×720。没有补帧。图片约 1672×941。逐段执行耗时以 素材索引.csv 和 records/*-video.json 为准，包含 ComfyUI 执行，不包含首帧重绘与人工复核。

采样使用当前可稳定运行的 FL2VA 剪枝 INT8 ConvRot、Qwen3VL NVFP4 AWQ 与 INT8 视频 VAE。此档用于比较材料和运动表达；细节分辨率不能等同于原生 720p。

两者位于 <LOCAL_PATH>/，与作者仓库 LFS SHA-256 一致。installed-loras.json 包含提交、文件哈希和大小。静态检查分别匹配 104 与 200 个底模目标矩阵，无缺失或尺寸不匹配；实际执行图、日志与视频记录另存于 records/。

工作流链：UNETLoader → Turbo LoRA → 风格 LoraLoaderModelOnly → BasicScheduler/BasicGuider → SamplerCustomAdvanced → VAE 解码 → 视频保存。Windows 下 LoRA 名称使用 ComfyUI 实际返回的反斜杠路径。风格 LoRA 强度是本轮试听参数。

H3 的 LoRA 与 SDXL、FLUX、Wan LoRA 分属不同底模，不能直接互换。此次没有加载未核验或要求不兼容底模的适配器。

## 怎样复用

1. 将对应 frames/*.png 放入 ComfyUI 的 input/FeishengStyleV11/。
2. 载入 workflows/*-API.json；确认模型名与已安装资源一致。
3. 改写视频提示词或种子后提交。相同首帧用于观察风格稳定性；先在本轮快速档确认效果，再提高原生分辨率或步数。

两组 LoRA 对照使用同一首帧、同一提示词、同一种子和同一 Turbo 8 步，仅开关风格适配器：16-C 人物电影质感、19-D 手绘线条群像。comparison/ 包含同步并排对照，clips/*-control.mp4 是关闭版。观察真实对照后再决定保留、减弱或关闭 LoRA。

本轮专用后台沿用低内存参数：动态 VRAM、关闭固定内存、2.5 GiB 显存余量、RAM 缓存 6/8 GiB。为隔离无关插件的启动阻塞，当前专用进程只加载原生节点；现有桌面安装与原启动器仍可照常使用。

源脚本位于 <PROJECT>/work/feisheng/style-v11/。ComfyUI 工作流、提示词、首帧、生成记录和视频均已单独保存，原成片与高清 v10 素材保持可用。
